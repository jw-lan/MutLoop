# S6 报告：真实缺陷的外部效度（RQ3）

> 代码：`scripts/s6_verify_sample.py`（样本前提验证）、`scripts/s6_run_flow.py`（单样本完整闭环）
> 数据：`data/s6/candidates.json`（候选）、`data/s6/verified_samples.json`、`data/s6/commit_counts.json`
> 过程中的踩坑、被推翻的方向见 [`DEVELOPMENT-LOG.md`](DEVELOPMENT-LOG.md) 的 S6 一节。

## 1. S6 要回答什么

**RQ3：变异分数能否换来"抓真实缺陷"的能力？**

这是整个项目的最终检验：平台主张"用变异分数替代覆盖率"，那么提升变异分数，
是否真的能抓到真实 bug？S6 用**修复前/修复后版本对**验证这条因果链。

## 2. 方法：修复前后对照 + AI 补测闭环

对每个 bug-fix commit（`C_bug` 修复前 → `C_fix` 修复后，改动的源码文件 `F`）：

1. **前提验证**（两条都成立样本才合格）：
   - 修复前测试套件在 `V_bug`（bug 代码）上**全过** → 证明测试弱、没抓到 bug
   - 修复后测试套件在 `V_bug` 上**有失败** → 证明 bug 真实存在
2. **找盲区**：在 `V_fix`（正确代码）上，用修复前测试跑变异测试，存活变异体 = 测试盲区
3. **AI 补测**：用 LLM 对存活变异体生成测试 `T_ai`（复用 S5 五轮流程，`root` 指向 V_fix）
4. **验证**：把 `T_ai` 拿到 `V_bug` 上跑，FAIL = 抓到了真实 bug

## 3. 四个关键工程点

1. **完整 git 历史**：`git fetch --unshallow` 补齐 5 个项目共 11870 个 commit，
   让自建 bug 标注无需 Docker/token。

2. **worktree 版本切换**：版本切换全在 `git worktree` 独立副本里做，不污染 subjects 主工作区。

3. **control 剔除 baseline 失败**：修复会同步改测试断言，导致"修复前测试在修复后代码上 FAIL"，
   需先跑 control 剔除这些测试再做变异判定。

4. **prompt 补全上下文**：给「带真实行号的代码 ±20 行 + 标注 class/def 边界」，
   flash 补测能力从几乎为 0 提升到能杀 7 个变异体。

## 4. 结果（批量 5 个功能类 bug 样本）

| 样本 | 变异体 | AI 杀死 | 抓到真实 bug |
|---|---|---|---|
| attrs/_make.py（错误消息 bug） | 2 | 2 | **1 ✓** |
| marshmallow/schema.py | — | 前提不成立（测试收集失败） | — |
| click/core.py | 9 | 2 | 0 |
| jinja/idtracking.py | 4 | 3 | 0 |
| attrs/_make.py（兼容性 bug） | 1 | 0 | 0 |

**4 个合格样本：AI 杀死 7 个变异体，抓到真实 bug 1 个。**

## 5. 结论（三层递进）

1. **闭环方法成立**：前提验证 → 找盲区 → AI 补测 → bug 版验证，全链路跑通，
   且在一个样本（`attrs/_make.py` 的错误消息 bug）上**完整走通并抓到真实 bug**。

2. **prompt 是 AI 补测的关键**：给足"方法签名 + 类名 + 真实行号"上下文后，
   flash 从几乎全败提升到能杀 7 个变异体——补测瓶颈一半在"喂给 LLM 的信息"而非 LLM 本身。

3. **"变异分数 → 抓 bug"的转化率低**：AI 杀死了 7 个变异体，但只有 1 个补测测试抓到了
   真实 bug（click 杀 2 抓 0、jinja 杀 3 抓 0）。根因是**盲区变异体与真实 bug 语义错位**——
   盲区是"测试没覆盖的任何行为"，bug 是"特定的错误行为"，二者只有落在同一可观察维度
   （如错误消息）时，补测测试才能"既杀变异体又抓 bug"。

## 6. 局限（如实报告）

1. **正面证据仅 1 个样本**，无法支撑"变异分数 → 抓 bug"的普遍结论。
2. **样本筛选成本高**：候选 353 个，符合"功能类 bug + 改动小 + 测试弱"的极少；
   测试强的项目（attrs/marshmallow 覆盖率 97%+）盲区小，不适合本实验。
3. **AI 补测能力边界仍在**：涉及库深层机制（版本判断、弃用警告）的变异体，补不了。
4. 简化版 bug 标注（fix-commit 次数），未做严格 SZZ blame 定位。

## 7. 结论一句话

**自动化补测闭环在方法上成立，但在"提升变异分数能否换来抓真实 bug"这个最终命题上，
受"盲区变异体与真实 bug 语义错位"限制，转化率低（1/4 样本）。** 这是对
"变异测试自动增强"理想的一次诚实检验。
